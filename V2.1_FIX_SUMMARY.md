# SourceGate v2.1 — Hardening Summary

## Why v2.1 exists

v2.0 proved reviewer attestation, complete-pair gating, typed reuse, and real StudioNet semantic paths, but a strict review found two higher-order risks:

1. after observing partial/negative semantic results, source-set mutation could be used to change the active basis;
2. frontend policy could hide contract refusal paths instead of proving them on-chain.

## Contract changes

- First successful pair judgment requires at least 3 active sources and all active sources already reviewer-attested.
- That transaction atomically seals the exact active source basis with `adjudication_basis_digest`.
- After adjudication starts, append / typed-source add / attest / revoke all revert.
- Any judged source exposes `judgment_locked = true`.
- Any `DERIVATIVE_SOURCE_CLUSTER` sets permanent `derivative_history_blocked = true`.
- Derivative-history claims can never freeze; a new claim id is required for a different basis.
- Freeze re-computes and verifies the sealed adjudication-basis digest before committing the final reusable basis.
- Final basis digest commits to the sealed adjudication-basis digest plus the complete pair matrix.

## Transaction and frontend changes

- Critical safe invalid calls are no longer hidden behind client-side role/eligibility gates.
- UI labels expected-refusal attempts explicitly, then lets the contract decide.
- Reads are pinned to finalized state.
- Writes wait for finalization, then verify an exact postcondition.
- If a finalized postcondition fails, the UI scans the finalized receipt/transaction for the contract's own refusal wording.
- Explorer transaction links are exposed in activity banners.
- Pair-history reads paginate past the 50-record page limit and require exact `pair_count` parity.

## New proof requirements

- 27 Direct Mode tests defined.
- Atomic rollback tests for partial `create_claim()` and upstream `reuse_count`.
- Same-call refused-before / succeeds-after tests for freeze and typed reuse.
- Blind natural StudioNet semantic protocol created; production vectors must not reuse fixture/prompt examples.
- `LOCKED_SPEC.md`, `BUILD_RULES.md`, and one-command `npm run verify` release integrity gate added.

## R1.5 Windows Direct Mode harness fix

- Added a Windows-only `genlayer-test 0.29.2` compatibility shim in `tests/direct/conftest.py`.
- The upstream Direct Mode loader replaces stdin with a temporary file and unlinks it while fd 0 still holds it open; Windows rejects that with `WinError 32`.
- The shim defers deletion until VM teardown restores stdin. It is test-harness-only and does not modify `contracts/SourceGate.py`.

## R1.6 Windows SDK compatibility fix

- Corrected the R1.5 Windows stdin shim to use the exact GenLayer SDK imports used by `genlayer-test==0.29.2`: `from genlayer.py import calldata` and `from genlayer.py.types import Address`.
- R1.5 incorrectly referenced helper attributes that are not exported by `gltest.direct.loader` in 0.29.2, causing every Direct Mode test to fail before contract deployment.
- This remains test-harness-only; `contracts/SourceGate.py` is unchanged.

## R1.7 Direct Mode atomic-revert harness correction

`genlayer-test 0.29.2` Direct Mode catches expected exceptions but does not automatically restore partial in-memory writes made before the exception. Production write transactions are atomic. The test harness now snapshots VM state on entry to `expect_revert()` and restores it on exit, so rollback assertions test production semantics. Contract bytes are unchanged.
